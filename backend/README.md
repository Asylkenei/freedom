# Freedom CQA — backend и проверка качества

Готовый транскрипт → OpenAI Responses → проверка доказательств → расчёт баллов baseline → SQLite → JSON API для отдельного frontend.

Проект создан отдельно от предыдущего MVP. Реализованы локальный API, неизменяемые версии чек-листов, апелляции с решениями человека, режим одной модели и ограниченный каскад двух моделей. Для независимой разметки и экспериментов есть offline-инструменты. Дизайн/frontend выполняет teammate; Speech-to-Text и обучение классификатора отсутствуют.

## Запуск

Нужен Python **3.11+**. Из папки проекта:

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
if (-not (Test-Path .env)) { Copy-Item .env.example .env }
```

Если `.env` уже существует, сохраните его: команду копирования повторять не нужно. В `.env` заполните:

```dotenv
CQA_API_KEY=ваш_секретный_API_ключ_OpenAI
CQA_MODEL=gpt-6.1-sol
CQA_BASE_URL=https://api.openai.com/v1
```

Ключ берётся в OpenAI Platform. Наличие ключа в файле не подтверждает его действительность или баланс. Переменные окружения имеют приоритет над `.env`, в том числе пустые значения. После изменения настроек перезапустите сервер.

```powershell
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000 --workers 1 --no-access-log
```

На Linux/macOS вместо `.\.venv\Scripts\python.exe` используйте `.venv/bin/python`, а для копирования — `cp .env.example .env`.

- Сервер: **http://127.0.0.1:8000**
- Проверка работы: **http://127.0.0.1:8000/api/health**
- Интерактивная документация: **http://127.0.0.1:8000/docs**
- OpenAPI: **http://127.0.0.1:8000/openapi.json**

Запускайте **один серверный процесс** на одну SQLite. Не используйте `--workers 2` и выше. Остановка — Ctrl+C. Пустая база не заполняется фальшивыми оценками или реальными клиентскими данными автоматически.

## Подключение teammate

Полная инструкция и пример JavaScript находятся в **FRONTEND_INTEGRATION.md**. Frontend обращается только к локальному backend. API-ключ не нужно передавать браузеру, добавлять в `VITE_*`, `NEXT_PUBLIC_*` или включать в URL.

Разрешены браузерные origins `http://localhost:3000`, `http://127.0.0.1:3000`, `http://localhost:5173`, `http://127.0.0.1:5173`. Другие указываются через `CQA_ALLOWED_ORIGINS` в `.env`, через запятую. Cookies/credentials не используются.

## Данные и хранение

Импортируется **JSON организаторов** или объект `{ "records": [...] }`. Данные 65 диалогов не включены в архив; teammate использует свой локальный JSON. Транскрипты уже готовы, распознавание речи не выполняется. У звонков доступна ссылка на запись, но сервер её не скачивает и не отправляет модели.

Сохраняются исходные время, текст, язык и роли. ID реплик `m0001`, `m0002`, … стабильны внутри неизменяемого диалога. Клиент, бот и система используются как контекст; оценивается оператор.

Повтор одинакового ID и содержимого пропускается. Иное содержимое с прежним ID возвращает **409** и откатывает весь пакет. Используйте новый ID для исправленного транскрипта. Импорт принимает до 2 000 диалогов, по 10 000 реплик на диалог; исходные строки сохраняются без обрезки/нормализации.

SQLite создаётся в `data/cqa.sqlite3` (путь меняется через `CQA_DATA_DIR`). Хранятся неизменяемые диалоги, версии чек-листа по hash и все запуски оценки со снимками правил/источников. Модель вызывается одним рабочим потоком. Готовый результат сохраняется сразу, независимо от браузера.

При перезапуске незавершённые `queued/running` помечаются `error/interrupted`. Автоматического повторного платного вызова нет. Готовые результаты и история остаются доступны.

## Модель и точность

По умолчанию используется одна **GPT-6.1 Sol** (`CQA_PIPELINE=single`). На каждом этапе: `reasoning.effort=medium`, `store=false`, максимум ответа 16 000 токенов; без `temperature=0`, автоматических повторов и переключения модели. Текущий чек-лист формирует строгую JSON Schema, включая новые ID и допустимые ступени.

Для явного включения каскада заполните настройки и перезапустите сервер:

```dotenv
CQA_PIPELINE=cascade
CQA_SMALL_MODEL=gpt-6-luna
CQA_REVIEW_MODEL=gpt-6.1-sol
CQA_REVIEW_ALL=false
CQA_AUDIT_RATE=0.10
CQA_SENSITIVE_CRITERIA=c03
```

Одна оценка вызывает модель один раз или два раза, никогда больше. Второй этап назначается при содержательной неопределённости/невалидных доказательствах, применимом чувствительном критерии, найденном флаге или детерминированном аудите. `CQA_REVIEW_ALL=true` включает проверку каждого диалога для эксперимента. `CQA_SENSITIVE_CRITERIA` задаёт ID чувствительных критериев; флаги чувствительны независимо от ID. Самооценка уверенности модели не используется для пропуска проверки.

Проверяющая модель оценивает полный транскрипт самостоятельно, без баллов первой. Недостающий решающий факт при отсутствии источников не восстанавливается её догадкой. Расхождение двух завершённых оценок по чувствительному критерию/флагу отправляется человеку. Ошибка обязательного второго этапа — `error`; первый этап остаётся в истории, но успешный финальный результат не публикуется. Режим каскада не включён по умолчанию: его преимущество ещё нужно измерить на независимом эталоне.

После LLM сохраняются проверки baseline: набор критериев, шкала/N/A, разрешённые роли, точные цитаты, диапазоны, продуктовые источники. **Цитата подтверждает сказанные слова, но не истинность финансового факта.** Смысловая правильность оценки требует проверки человеком и независимой разметки.

Основной балл вычисляет код, а не LLM. Семь взвешенных критериев нормируются до 100 с исключением N/A; восьмой — отдельный флаг. Флаг нарушения не обнуляет балл. Неопределённый взвешенный критерий делает полный итог `null`. Неопределённый флаг может оставить числовой итог, но вся оценка будет `needs_review`, а флаг — `null`.

Ошибки сети/ключа/квоты/JSON/refusal/incomplete — `error`, без результата. Неподтверждённый факт или отклонённая цитата — `needs_review`, без фиктивной положительной оценки по этому критерию. Это разные состояния.

### Продуктовые источники

По умолчанию внешняя база отсутствует. При необходимости создайте приватный JSON по образцу `knowledge.template.json` и задайте `CQA_KNOWLEDGE_FILE`. Реальные тарифы/инструкции в исходники не выдумываются. Источники перечитываются при создании задания и сохраняются его неизменяемым снимком; изменение источников меняет ключ кэша. Если решающий для оценки факт не подтверждён, модель должна вернуть `needs_review`. Отсутствие справочника не означает, что все консультации неоцениваемы.

## Кэш, ошибки и повтор

Ключ кэша учитывает разговор, чек-лист, источники, обе модели, промпты, параметры адаптера, версию маршрутизации, аудит и адрес API. Одинаковый запрос возвращает сохранённую оценку **без нового вызова**, включая ранее сохранённую ошибку. Переход с первой версии backend на новую конфигурацию может создать другой ключ кэша; старые результаты остаются в истории.

Для нового запуска передайте `force:true`. Предыдущий результат сохранится. Пока работа ещё `queued/running`, повтор, в том числе с `force:true`, возвращает тот же ID. После исправления ключа сначала перезапустите сервер, затем явно повторите ошибочную оценку с `force:true`.

Нормализованный usage в `inference.usage`: `prompt_tokens`, `completion_tokens`, `total_tokens`, `cached_input_tokens`, `reasoning_tokens`, если они выданы провайдером. `completion_tokens` уже включает reasoning. `calls` суммирует вызовы этапов; `duration_seconds` — обработка без очереди. Ответы, usage и задержка каждого этапа находятся в `stages`. При неполном usage `usage_complete=false`; пустой usage не означает бесплатный запрос.

`inference.estimated_usd` — ориентировочная сумма токенов обоих этапов по стандартным тарифам из `costs.py` на 07.11.2026. Для неизвестной модели, неполного usage и длинного контекста стоимость `null`. Это не счёт: cache-write, региональные и другие тарифные доплаты не включены; допущения сохранены в каждом этапе. Перед массовым запуском обновите цены по официальной странице.

`original_findings`/`original_summary` относятся ко всей автоматической цепочке до вмешательства человека. Отдельный ответ маленькой модели находится в `stages[0]`. После апелляции меняются только `final_findings`/`final_summary`; исходная автоматическая оценка сохраняется.

## Чек-листы и апелляции

`POST /api/checklists` принимает `{checklist, parent_hash, author}` и возвращает новую версию с hash; повтор идентичного содержимого возвращает существующую. `GET /api/checklists/{hash}` читает конкретную версию. Исторические версии и их снимки не изменяются. Новые критерии поддерживаются через конфигурацию, без правки кода. Схемы запросов — в `/docs`, примеры — в `examples/`.

`POST /api/evaluations/{id}/appeals` создаёт обращение; `GET` того же пути читает историю. `POST /api/appeals/{id}/resolve` подтверждает или меняет оценку и атомарно пересчитывает итог. Для решения нужны основание, проверяющий, текущая `expected_revision` и уникальный `client_request_id`. Повтор того же запроса не применяет решение снова; другое содержимое под тем же ID или устаревшая ревизия возвращает 409. Все решения применяются к снимку правил конкретного запуска. В демо автор/проверяющий — поля аудита, не аутентифицированные аккаунты.

## Независимая разметка

PDF содержит критерии, но не готовые метки 65 диалогов. Инструменты не вызывают OpenAI и не заполняют человеческие оценки автоматически.

```powershell
python annotation.py prepare --data "C:\путь\к\dev_response.json" --out data/annotation-v1
```

Добавьте `--development-id ID` для каждого уже изученного/использованного диалога. В локальном подготовленном пакете четыре smoke-примера уже исключены из контроля. Получаются `manifest.json`, `development.blind.json`, `test.blind.json` и CSV для заполнения. Для официальных 65 записей распределение 45/20: RU-чаты 22/8, KZ 10/5, EN 10/5, RU-звонки 3/2. Точные дубли группируются; похожие пары между частями выносятся на человеческую проверку. Непустая папка не перезаписывается.

Разметчик читает `messages` и `checklist_snapshot` в слепом JSON. Заполняет CSV или `findings` JSON: `status=scored|na|unresolved`, допустимый `score` или `null`, `reason`, точные `evidence`, `checked_span` для отсутствующего действия, `na_reason`, продуктовый источник при необходимости. Для каждой метки нужны `annotator_id`, `annotation_state=adjudicated` после согласования и правдивый `ai_assisted`. N/A разрешён только по условию чек-листа; неизвестность — `unresolved`. На контрольных метках AI-предразметка запрещена. Отдельно укажите `reviewer_id`, если метку проверил второй человек.

В CSV поля `evidence`, `checked_span`, `knowledge_evidence`, `verification_limits` содержат JSON. Например: `[{"message_id":"m0010","quote":"точный фрагмент"}]`, `{"from":"m0010","to":"m0012"}`; пустое отсутствие диапазона — `null`. `ai_assisted` — `true`/`false`.

```powershell
python annotation.py from-csv --template data/annotation-v1/development.blind.json --csv data/annotation-v1/development.labels.csv --out data/development.reviewed.json
python annotation.py export --annotations data/development.reviewed.json --data "C:\путь\к\dev_response.json" --out data/development.gold.json
python annotation.py agreement --left data/annotator-a.json --right data/annotator-b.json --data "C:\путь\к\dev_response.json" --out data/agreement.json
```

Для сравнения двух разметчиков допускаются состояния `submitted`/`adjudicated`. Совпадение разметчиков не равно точности; совпадения автора двух файлов отчёт отмечает отдельно. В итоговый gold допускаются согласованные метки; незаполненный шаблон, недопустимые баллы, выдуманные цитаты или изменённый транскрипт отклоняются. Нерешённые критерии сохраняются отдельно, остальные метки того же диалога продолжают участвовать в сравнении. Итог gold рассчитывается кодом.

## Ограниченные эксперименты и метрики

По умолчанию следующая команда только строит план и не запускает модель:

```powershell
python experiments.py --data "C:\путь\к\dev_response.json" --manifest data/annotation-v1/manifest.json --split development --limit 4 --max-calls 8 --out data/experiments/dev-01
```

Для выполнения добавьте `--execute`. Для каскада резервируется до двух вызовов на диалог, для single — один. `--force` явно создаёт новую платную оценку вместо кэша. При первой ошибке очередь эксперимента останавливается, автоматического повтора нет. Исходные данные, manifest и серверная конфигурация проверяются; каждое задание содержит `pipeline_hash`, изменение конфигурации возвращает 409 до вызова модели. Отчёт и `predictions.json` сохраняются после каждого результата. Повторная запись в папку выполненного эксперимента отклоняется.

Перед контролем завершите настройку на development, проверьте похожие пары и сохраните профиль через `--freeze-out data/frozen.json` в команде планирования. Контроль запускается с `--split test --frozen data/frozen.json`; hash модели, manifest и чек-листа должны совпадать. На контрольных данных модель/промпт/правила больше не подбирают.

```powershell
python benchmark.py compare --gold data/development.gold.json --predictions data/experiments/dev-01/predictions.json --out data/metrics.json
```

По умолчанию сравнивается автоматическая цепочка `original`. Для анализа доступны `--stage primary`, `review`, `final`; последний включает ручные решения и не является метрикой автоматической системы. Формат v1 baseline сохранён. Gold v2 проверяет шкалы даже при отсутствующих предсказаниях и поддерживает нерешённые эталоны, ошибки API, разбивку по критерию/языку/каналу, N/A, полноту ответа, точность флагов, валидность цитат, MAE итога, задержки и известную стоимость. Число случаев и пропуски показываются явно. Смысловую правильность доказательств проверяет человек.

## Проверка

```powershell
.\.venv\Scripts\python.exe -m unittest discover -v
```

Проверки не вызывают OpenAI: используются синтетические фикстуры, включая настоящий локальный HTTP-сервер с контрактом Responses. Сохранены все 38 исходных проверок baseline; транспортная фикстура обновлена под Responses. Проверяются API, очередь, кэш, перезапуск, ошибки, CORS и отсутствие ключа в ответах.

В `examples/` лежат **только синтетические** примеры импорта и состояний API: `completed`, `needs_review`, `error`. Это примеры контракта, не доказательство точности модели. Подробные результаты проверки — **VERIFICATION.md**.

### Четыре реальных прогона, явный запуск

Сначала запустите backend с действующим ключом, затем:

```powershell
.\.venv\Scripts\python.exe smoke_live.py --data "C:\путь\к\dev_response.json"
```

Скрипт выбирает ровно четыре записи: RU-чат, KZ-чат, EN-чат, RU-звонок. Импортирует только их, запускает через API по очереди, проверяет сохранённые цитаты и записывает usage/задержку в приватный `data/live-smoke-summary.json`. После первой ошибки останавливается и не отправляет оставшиеся записи.

Если старая ошибка уже сохранена и её причина исправлена, явный ручной повтор:

```powershell
.\.venv\Scripts\python.exe smoke_live.py --data "C:\путь\к\dev_response.json" --retry-errors
```

Флаг повторяет только ошибку, уже сохранённую до запуска. Свежая ошибка не повторяется автоматически. Все 65 записей скрипт не оценивает. Эти четыре случая проверяют доступ и маршрут, а не общую точность; для неё нужен независимый заполненный gold и `benchmark.py`.

## Границы и передача

- Нет frontend: интерфейс редактора чек-листа и апелляций подключает teammate через реализованный API.
- Нет авторизации/публичного деплоя: процесс привязан к 127.0.0.1. Перед доступом из сети нужен отдельный эксплуатационный контур.
- Нет speech-to-text и акустического анализа. Дикция/темп/интонация по тексту не оцениваются; у звонков сохраняются ограничения проверки.
- Нет RAG и внешнего поиска. Переданные локальные продуктовые источники отправляются модели целиком.
- Автоматическое удаление персональных данных из транскриптов не реализовано. Транскрипт отправляется выбранному API только при явном запуске оценки; отправлять можно только материалы, доступные команде для этой обработки.

`.env`, SQLite, транскрипты, реальные ответы и журналы находятся вне выдаваемого архива и исключены из Git. Ключ для teammate настраивается отдельно. Для распространения предназначены исходники, зафиксированные зависимости, документация, OpenAPI и синтетические примеры.

Официальная документация: [GPT-6.1 Sol](https://developers.openai.com/api/docs/models/gpt-6.1-sol), [Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs?api-mode=responses).
